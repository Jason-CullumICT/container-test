3. Executive Summary

  1. Runtime crash in BugDetail: onUpdate is called after orchestrator submit but is not declared in the component props — every successful bug submission will throw a ReferenceError. [P1]
  2. Phantom specification: All 6 new // Verifies: FR-REPO-SELECTION traceability comments reference a requirement ID that does not exist in any specification document. [P1]
  3. FeatureRequestDetail silently drops repo selection: The selected repo is never passed to orchestrator.submitWork(), so the user's repo choice is ignored. [P3]
  4. Hardcoded repo list duplicated 5+ times across 3 files: Adding a new repo requires editing 3 files in 5 locations. The merge logic is also copy-pasted. [P2]
  5. No URL validation on API-supplied or stored repos: Repo URLs from the API and database are rendered and submitted to the orchestrator without any scheme/domain validation, enabling repo-spoofing attacks (especially given the existing no-auth P1). [P2]

The primary fix intent (make work-backlog available in all repo dropdowns) works correctly under all tested failure modes. However, the implementation introduces 2 P1 regressions and significant code quality issues that must be addressed before merging.

9. P1 Findings

P1 — QUAL-002 / PERF-001 / CHAOS-006: BugDetail calls onUpdate which is not in component props

FileSource/Frontend/src/components/bugs/BugDetail.tsx:124
CategoryRuntime Error / Missing Prop
StatusNEW
SpecialistsQuality Oracle, Performance Profiler, Chaos Monkey

Description: BugDetailProps declares only bug and onClose. After a successful orchestrator submission, handleSubmitToOrchestrator calls onUpdate(updated) which does not exist in scope. This is a TypeScript compile error and a guaranteed runtime ReferenceError.

Exploit scenario: User opens any bug, clicks "Submit to Orchestrator", submission succeeds, component immediately crashes with unhandled exception. The bug status may have been updated server-side but the UI shows an error state.

Impact: Complete breakage of the bug submission flow. Every successful submit crashes.

Recommendation: Add onUpdate: (updated: BugReport) => void to BugDetailProps and destructure it in the function signature, matching the pattern in FeatureRequestDetail.

P1 — QUAL-001: FR-REPO-SELECTION does not exist in any specification

FileAll 3 changed files (6 // Verifies: comments)
CategorySpec Compliance / Traceability
StatusNEW
SpecialistsQuality Oracle

Description: Six // Verifies: FR-REPO-SELECTION comments reference a requirement ID that does not exist in Specifications/dev-workflow-platform.md or any other spec document. The traceability enforcer does not catch this because it only validates numeric FR IDs. This violates the architecture rule: "Every decision and line of code must trace back to a specification."

Impact: Phantom traceability — the code appears traced but the spec doesn't exist. Future audits and developers will assume coverage that is not there.

Recommendation: Write a proper FR specification entry (e.g., FR-096) in the spec document covering repo selection defaults, then update all // Verifies: comments to use the real ID.
