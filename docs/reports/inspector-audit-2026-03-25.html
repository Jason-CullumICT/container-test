3. Executive Summary

  1. Unauthenticated file upload creates an attack chain to stored XSS/RCE: All image endpoints lack authentication. MIME validation is client-header-only (bypassable). File extensions are preserved from attacker input. SVG files with embedded scripts can be uploaded and served to any user. This is the highest-priority chain (SEC-021 + SEC-022 + SEC-023 + SEC-028).
  2. Non-atomic create+upload flow causes data integrity issues: Entity creation and image upload are two separate calls with no rollback. Upload failure after entity creation leaves orphaned records and confuses users (CHAOS-021).
  3. Sequential image ID generation is fragile and has a latent overflow bug: IMG-NNNN text-based IDs will collide after 9999 images due to lexicographic sorting. Multiple specialists flagged this independently (SEC-027, QO-011, PERF-023, CHAOS-023).
  4. File deletion order creates permanent orphans on crash: DB record is deleted before the file. Process kill between the two operations leaves unreferenced files on disk forever (CHAOS-025).
  5. No rate limiting + no disk quota = trivial disk exhaustion DoS: Unauthenticated users can fill the server disk with unlimited 25MB upload batches (SEC-025).

9. P1 Findings

P1 NEW SEC-021: MIME Type Filter Bypassed via Content-Type Spoofing

Category: OWASP A03 — Injection / Unrestricted File Upload

File: Source/Backend/src/middleware/upload.ts:30-36

Description: The fileFilter checks file.mimetype which is the client-supplied Content-Type header. No magic-byte validation. Combined with preserved file extensions (SEC-022), attacker uploads arbitrary files (SVG with scripts, PHP shells) that pass the filter.

Exploit: Upload shell.svg with Content-Type image/jpeg → stored as <uuid>.svg → served via /uploads/ → browser executes inline JavaScript → stored XSS on any visitor.

Recommendation: Add magic-byte validation using file-type library. Force stored extensions from a safe whitelist derived from validated magic bytes, never from originalname.

P1 NEW SEC-023: All Image Endpoints Completely Unauthenticated

Category: OWASP A01 — Broken Access Control / A07 — Auth Failures

Files: Source/Backend/src/routes/bugs.ts:142-208, Source/Backend/src/routes/featureRequests.ts:222-289

Description: POST/GET/DELETE image endpoints have zero authentication. Any network-accessible caller can upload files to disk, enumerate images, or delete all images.

Exploit: Anonymous user sends unlimited upload requests → fills disk. Anonymous user enumerates and deletes all images via sequential IDs.

Recommendation: Add JWT/session auth middleware globally to all /api/* routes.

P1 NEW PERF-023: N+1 ID Generation with Lexicographic Overflow Bug

Category: Performance / Data Integrity

File: Source/Backend/src/services/imageService.ts:42-50

Description: generateImageId() runs a SELECT per file in a multi-file upload (up to 5 queries). IDs use IMG-NNNN text format with ORDER BY id DESC string sort — IMG-10000 sorts before IMG-9999, causing ID collisions after 9999 images.

Recommendation: Replace with UUID-based IDs. The uuid package is already a project dependency.

P1 NEW CHAOS-021: Non-Atomic Create+Upload Leaves Orphaned Entities

Category: State Invariant / Partial Write

Files: Source/Frontend/src/pages/BugReportsPage.tsx:45-52, Source/Frontend/src/pages/FeatureRequestsPage.tsx:46-53

Description: Entity creation and image upload are two sequential API calls. If upload fails after entity creation, the entity persists but user sees an error and retries, creating duplicates. No rollback mechanism.

Recommendation: Show partial-success message ("Bug created, image upload failed — add images from detail view") or decouple upload from create flow.

P1 NEW CHAOS-023: Sequential ID String-Sort Collision Under Concurrency

Category: Data Integrity

File: Source/Backend/src/services/imageService.ts:42-50, 80-95

Description: generateImageId() uses string-ordered ORDER BY id DESC LIMIT 1 which breaks at 5-digit numbers. Concurrent requests may generate duplicate IDs. Same root cause as PERF-023 and SEC-027.

Recommendation: Use uuidv4() for image IDs.

15. Recommendations

Block Deployment

  1. Add magic-byte file validation — Install file-type, validate uploaded file content against actual magic bytes, force safe extensions. Resolves SEC-021, SEC-022, DEP-014.
  2. Add authentication middleware — Gate all /api/* routes behind JWT/session auth. Resolves SEC-023, SEC-024, SEC-025, SEC-028 and reduces exploitability of all other findings.
  3. Replace sequential IMG IDs with UUIDs — Use uuidv4() (already a dependency) for image IDs. Resolves PERF-023, SEC-027, SEC-029, QO-011, CHAOS-023 (5 findings, 4 specialists).
  4. Add entity ownership check on image delete — Verify image.entity_id === requested entity before deleting. Resolves SEC-024.

This Sprint

  1. Reverse file deletion order — Delete file first, then DB record. Resolves CHAOS-025.
  2. Add partial-success handling for create+upload — Show specific message when entity created but upload failed. Resolves CHAOS-021.
  3. Switch to async filesystem ops — Replace fs.existsSync/fs.unlinkSync with async equivalents. Resolves PERF-024, PERF-025, CHAOS-020.
  4. Add rate limiting to upload endpoints — Install express-rate-limit, configure per-IP limits. Resolves SEC-025.
  5. Add Cache-Control headers to /uploads static serving — Resolves PERF-027.
  6. Add X-Content-Type-Options: nosniff to uploaded files — Resolves SEC-028 (partial).
